# 3D FOOH 규칙

실사 영상에 Blender에서 만든 3D 오브젝트·캐릭터를 넣고 After Effects에서 합성하는
규칙입니다. 캐릭터 모델은 ComfyUI의 Tripo API 노드로 만듭니다. 기준 사례는 다음
세 편이며, 모두 배치 영역의 독립 검수에서 1920×1080 기준 **p95 1.5 px 이하, 최대
3 px 이하**를 통과했습니다.

| 사례 | 내용 | 카메라 경로 | 독립 검수 |
| --- | --- | --- | --- |
| FOOH08 | 건물 벽이 열리며 공 468개가 쏟아짐(Bullet) | COLMAP + 장면 직선으로 구한 고정 초점 | 지면 독립점 51개, p95 1.166 / 최대 2.518 px |
| FOOH09 | 거리에 선 거대 마스코트의 인사(Tripo) | 건물 직선으로 맞춘 고정 카메라 | 피팅에 안 쓴 직선 14개, p95 0.746 / 최대 0.993 px |
| FOOH11 | 드론 농구장 위 토끼의 달리기·점프(Tripo) | 고정 기준점 ECC 평면 추적 + 평면 카메라 | 코트선 끝점 1,402개, p95 0.984 / 최대 1.362 px |

수치(초점, 카메라 높이, 시뮬레이션 설정)는 그 샷의 값입니다. 새 샷에서는 같은
방식으로 다시 정하고 `work/<shot>/contract.json`에 먼저 적습니다.

## 1. 도구 역할

| 단계 | 도구 | 역할 |
| --- | --- | --- |
| 원본 준비 | FFmpeg·ffprobe | 유리수 FPS·프레임 수·전체 디코드 확인, 작업 프레임 추출 |
| 카메라 | COLMAP([AFTEREFFECT_COLMAP](https://github.com/hyun2xyz/AFTEREFFECT_COLMAP)), OpenCV, Mocha AE | 샷에 맞는 경로 하나를 고릅니다(3장) |
| 독립 검수 | OpenCV | 카메라 계산에 쓰지 않은 점·선으로 오차를 잽니다 |
| 3D 모델 | ComfyUI + Tripo API 노드 | 모델·자동 리깅·애니메이션을 한 번에 생성 |
| 3D 작업 | Blender LTS(백그라운드 Python) | 카메라·회색 테스트·모델 정리·접지·물리·렌더 패스 |
| 합성 | After Effects | 원본과 CG 레이어를 분리한 편집 가능한 프로젝트 |

## 2. 플레이트를 고정합니다

- 원본의 해상도, 유리수 FPS(예: 30000/1001), 사용 구간, 크롭·리사이즈를 기록합니다.
  보간으로 만든 슬로모션이나 임의 리타임을 쓰지 않습니다.
- 카메라 계산 전에 배치할 위치(바닥·벽의 어느 영역)와 검수 기준, 검수에 쓸 점·선을
  정합니다. 검수용 관측은 카메라 계산에 넣지 않습니다.
- 사람·차·그림자·반사처럼 움직이는 것은 배경 기하에서 뺍니다.

## 3. 카메라 경로를 고릅니다

샷마다 맞는 경로가 다릅니다. 하나를 고르고, 통과하지 못하면 다른 경로를 새로 시험합니다.
실패한 결과를 다듬어 통과처럼 보이게 하지 않습니다.

**A. 카메라가 거의 움직이지 않는 거리·건물 샷 → 직선 기반 고정 카메라(FOOH09)**
- 건물의 수직·수평선, 보도 경계 같은 직선으로 소실점을 구해 초점과 자세를 맞춥니다.
- 피팅에 쓰지 않은 직선의 끝점으로 검수합니다.
- 시차가 거의 없으면 깊이·축척을 알 수 없습니다. 카메라 높이(예: 1.65 m), 오브젝트
  크기는 아티스트 가정으로 적습니다. 자유 깊이 SfM이라고 부르지 않습니다.

**B. 시차가 있는 이동 샷, 질감 있는 장면 → COLMAP(FOOH08)**
- [AFTEREFFECT_COLMAP](https://github.com/hyun2xyz/AFTEREFFECT_COLMAP)으로 카메라를 풉니다.
- 앞으로 나아가며 바닥이 화면 대부분을 차지하는 샷은 자유 초점이 무너질 수 있습니다.
  FOOH08에서 자유 초점은 695.7 px로 나왔지만 장면 직선은 1451.2 px를 가리켰습니다.
  이때 장면 직선으로 초점을 구해 **고정**하고 다시 풉니다.
- 등록된 프레임 수나 내부 오차가 아니라, 바닥의 독립 관측점으로 검수합니다.

**C. 넓은 평면 위에 놓는 샷(코트·광장 바닥, 드론) → 평면 추적 카메라(FOOH11)**
- 바닥 평면을 Mocha 또는 고정 기준점 ECC로 추적해 프레임별 호모그래피를 구합니다.
- 고정 초점(가정)과 알려진 크기(예: 코트 원 반지름)로 평면 카메라를 만듭니다.
- 배치는 **추적한 평면 위**로 제한합니다. 평면 밖의 높이·깊이는 검증되지 않습니다.
- 코트선처럼 피팅에 안 쓴 선의 끝점으로 검수합니다.

공통 기준: 배치 영역의 독립 검수 p95 1.5 px 이하, 최대 3 px 이하(1920×1080).
최악 프레임 값도 함께 남기고, 측정 못 한 프레임은 분모에 UNKNOWN으로 둡니다.
통과하지 못하면 다음 단계로 가지 않습니다.

## 4. 회색 부착 테스트

- 카메라를 Blender로 옮깁니다. FPS(fps와 fps_base), 시작 프레임, 센서 폭과 초점,
  주점, 축 변환, 단위를 기록합니다. Blender 프레임과 AE 시간의 대응을 명시합니다.
- 바닥·벽에 **고정된 회색 상자**를 놓고 전체 구간을 렌더해 원본 위에 겹칩니다.
  시작·중간·끝과 움직임이 가장 큰 구간에서 미끄러짐을 봅니다.
- 회색 테스트를 통과한 뒤에만 캐릭터·물리·재질로 넘어갑니다.

## 5. ComfyUI Tripo로 3D 모델 만들기

- ComfyUI 데스크톱을 로컬(127.0.0.1)에서 실행하고 Comfy 계정에 로그인합니다.
  Tripo 같은 Partner(API) 노드는 **선불 크레딧**을 씁니다. 실행 전에 노드가 표시하는
  예상 크레딧을 보고 학생이 승인합니다.
- 기준 사례의 그래프:
  `TripoPSeriesTextToModelNode`(P2, PBR, UV 내보내기, 면 수 상한 20,000, 시드 고정)
  → `TripoRigNode`(biped, glb) → `TripoRetargetNode`(프리셋 애니메이션, 제자리 애니메이션,
  지오메트리 포함) → 단계별 `Save3DAdvanced`(base·rigged·animated GLB).
- 프롬프트 규칙(리깅이 잘 되는 형태): 한 캐릭터 전신, 정면 A-포즈, 좌우 대칭, 팔·다리가
  몸과 떨어져 보임, 납작한 발바닥, 받침대·배경·글자·소품 없음. 네거티브 프롬프트에
  "fused limbs, crossed legs, extra limbs, floating fragments, feet merged" 등을 넣습니다.
- 그래프는 API 형식 JSON으로 저장하고 **한 번만 제출**합니다. 제출 전에 시도 기록을
  남기고, prompt_id를 받습니다. 결과가 불분명하면 다시 보내지 말고 ComfyUI의
  `/history`와 `/queue`부터 확인합니다(같은 유료 작업이 두 번 돌 수 있습니다).
- 받은 GLB 세 개와 prompt_id·시드·파일 크기를 기록합니다.

## 6. 모델 검사와 정리

- Blender 백그라운드에서 GLB를 열어 크기·위쪽 축·피벗·면 수를 확인합니다.
- 목·어깨 같은 곳에 뚫린 구멍(경계 가장자리)이 있으면 그 부위만 메우고,
  **발 정점은 바꾸지 않습니다**(접지가 틀어집니다).
- 재질은 PBR 텍스처를 유지합니다. 크기는 장면 가정(예: 캐릭터 키 5 m)에 맞춰 적습니다.

## 7. 애니메이션 접지

- 제자리 애니메이션을 샷 길이에 맞춰 다시 배치하고, 서 있는 구간은 루트·골반·
  다리를 고정합니다. 이동은 카메라가 아니라 캐릭터의 위치 키로 만듭니다.
- 발 접지를 **1/4 프레임 단위**로 확인합니다. 발바닥과 바닥의 간격(몇 mm), 서 있는
  발의 미끄러짐, 무릎의 순간 이동량을 잽니다. 튀는 곳은 지지 IK로 고칩니다.
  FOOH07에서는 무릎의 1/4 프레임 이동 47.85 mm를 지지 IK로 19.42 mm까지 줄였습니다.
- 착지·점프가 있으면 손·발이 바닥을 뚫지 않는지 최악 프레임을 확대해 봅니다.

## 8. 물리 시뮬레이션(선택)

- Blender Bullet 강체를 실제로 굽습니다. 먼저 자유낙하·바닥 반발 같은 단순 검사를
  하고 많은 물체로 넘어갑니다.
- 기준 사례 설정: FOOH08 공 468개(질량 0.4, 반발 0.72, 마찰 0.28, 서브스텝 12,
  솔버 반복 45), FOOH12 큐브 128개(서브스텝 20, 솔버 반복 50, split impulse).
- 다 구운 캐시는 다시 굽지 않습니다. 새 프로세스에서 캐시를 다시 재생해 프레임·
  물체 수·위치가 같은지 확인합니다.
- 바닥·물체 간 관통(예: 1 cm 이내), 실제 튕김 횟수, 정착을 따로 잽니다.
- Blender 5.2.1에서는 새 강체 캐시의 디스크 캐시를 Python으로 켜는 순간 종료되는
  문제가 있었습니다. 캐시 이름과 인덱스를 먼저 정한 뒤 켜거나, 메모리에서 굽고
  변환 행렬을 따로 내보냅니다.

## 9. 렌더 패스

- 같은 카메라·같은 프레임 시계로 회색, 재질, 조명·그림자, 최종 패스를 렌더합니다.
  패스마다 셰이딩만 바뀌고 카메라·물체·시간은 같아야 합니다.
- 접지 그림자는 그림자 받는 면(Shadow Catcher)으로 따로 뽑습니다.
- 원본 한 프레임을 반사·조명 참고로 쓸 수 있지만, 측정한 환경광이 아니라고 적습니다.
- straight 알파의 RGBA 시퀀스(PNG 16bit 또는 EXR)로 렌더합니다.

## 10. After Effects 합성

- 새 프로젝트로 만들고, Python이 만든 JSX를 학생이 **File → Scripts → Run Script File**로
  실행합니다. 기준 사례 설정: 16 bpc, Rec.709 Gamma 2.4, linear blending.
- 원본, CG, 접지 그림자를 각각 편집 가능한 레이어로 둡니다.
- 광학 맞춤은 CG에만 적용합니다: 원본에 맞춘 약한 블러(예: 0.8 px), 그레인(예: 0.6/255),
  노출·색. 색 보정이나 블러로 카메라 실패를 숨기지 않습니다.
- 최종 MP4는 전체 디코드하고 프레임 수·시간·색 태그(BT.709, TV range)를 확인합니다.
  RGB→YUV 행렬이 BT.709인지 확인합니다(601로 잘못 들어가면 색이 틀어집니다).

## 11. 브레이크다운(선택)

- 3장의 카메라 기준과 회색 부착을 통과한 결과로만 만듭니다.
- 결과·원본·추적·모델·애니메이션·재질·조명·결과를 **같은 원본 시계**로 이어 붙입니다.
  실제로 하지 않은 과정을 화면처럼 꾸미지 않습니다.

## 12. 보고
